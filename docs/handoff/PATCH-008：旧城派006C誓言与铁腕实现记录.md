# Patch 008：旧城派、006C「誓言与铁腕」实现记录

## 完成范围

- 新增 `data/oath_order.json` 与严格配置加载器，登记旧城派阈值、增长/衰减、倒计时、006C 解锁、签署关系、路线行动成本和冷却。第六批补表数值统一声明为 `TEST_NUMERIC`。
- 将第 24 天南方来信实现为旧城派固定事件，不进入普通随机事件队列。建立参考人口、低/中/高阈值、阶段事件一次性记录、人数趋势、D37 增员选择接口、专属承诺、倒计时和 D48 前最终结算。
- 新增 `game.resolve_old_city_event`。旧城派待处理阶段事件属于 C 级硬阻断；失败请求不改变状态，成功请求原子提交选择及结果。
- 实现旧城派散去、部分离开和大规模离开。离开不计死亡、不产生遗体、不直接触发硬失败；人口与岗位汇总确定性扣减，正式工程师最后扣减并保留至少 2 人，资源不降为负数。
- 新增 006C 页面解锁：D30 且已签署至少 8 条 006A 社会炉律时普通开放，D35 保底开放。006A 与 006C 使用独立冷却；006C 每次签署后冷却 2 天。
- 新增 `game.sign_oath_order_law`。誓言路线与铁腕路线永久互斥；首条路线炉律必须明确确认；签署历史、前置关系、日期和下一次可签署日写入 v10 存档并严格校验。
- 守炉堂与巡查所采用独立特殊设施状态：进入对应路线时自动启用并显示，不通过 `game.build` 建造，不进入普通建筑表，不占区域槽位，不使用供热，也不受温度或炉心关闭影响。
- 新增 `game.staff_oath_order_facility`。至少派驻 1 名正式工人或工程师后设施运行；特殊设施与普通建筑、资源点共享正式成人岗位总量，不能重复分配同一人口池。
- 新增 `game.use_oath_order_action`，实现守炉誓言、丧钟悼念、共食、留下劝说、巡查、统一通告、临时扣留与户籍核验。资源不足、设施未运行、炉律未签署、目标不存在或冷却未结束时均不付款、不结算效果、不写入冷却。
- 丧钟悼念只将当日死亡引发的恐慌后效减半，不复活人口、不处理遗体，也不取消死亡的其他基础影响。
- 最终誓言只免除 `trust_exile` 轴并登记 `oath_carried_zero_trust` 候选标签；最高命令只免除 `panic_expelled` 轴并登记 `decree_carried_panic`。人口归零、炉心崩溃和另一条情绪失败轴仍正常生效。
- 机器观察新增旧城派视图、006C 路线/设施视图和四项命令 schema；不提供行动评分、推荐或自动策略。
