# Patch 024：事件文案与机器可发现性实现记录

## 来源与范围

本轮依据 Patch 023 合并后 seed `23023` 的 D1～D12 纯黑盒验收继续处理三类可理解性问题：日结确认令牌的会话范围只能在失败后发现、规则栏目及建筑成本前置缺少可发现入口、事件面板存在已经封存却未接入运行时的文案。D10 遗体警告同时暴露结算前快照与结算后结果缺少时间阶段标识。

本轮不调整地图、资源、产能、科技、炉律、事件效果、社会路线、天气、终霜门槛或其他平衡数值；不新增推荐行动、决策评分、自动策略、图形界面、D56 或 Patch 025。

## 封存事件文案接线

- 以 `docs/text-assets/第 5 轮：Event  Promise  OldCity  FixedArrival  FrostWarning  Achievement.md` 为唯一正文来源，补齐当前正式事件面板中已经标记为“已封存原文”或“用户确认覆盖项”的标题、正文与 A/B/C 选项。
- 覆盖食物、医疗、遗体、儿童、工时、煤炭、炉心、寒屋、信任和恐慌事件；其中包括黑盒局实际遇到的“第一具遗体”“煤仓见底”和“长班后的倒下”。
- “长班后的倒下”“加班后的空位”、D6/D19/D37 固定增员和“第七霜落”正文仍未封存。它们只显示已封存标题与选项，正文继续返回稳定 `text_id`、`body_text=null` 和 `body_status=TODO_TEXT`，不写入占位句或自创文案。
- 注册表测试逐项锁定所有运行事件面板的封存覆盖，并明确锁定上述未封存正文仍不进入 TextRegistry。

## 规则与命令发现

- 正式 `Observation` 新增排序稳定的 `available_rule_sections`，列出 `buildings`、`events`、`final_frost`、`laws`、`maps`、`oath_order`、`survival` 与 `technologies`。
- `protocol_contract.rules_query` 返回纯协议请求形状、可用栏目及“返回验证后配置、不包含策略推荐”的机器合同。
- `CommandSpec.related_rule_sections` 标记命令对应的规则来源。Patch 024 为全部建筑、派员、地表采集、供热和 woodfuel 命令指向 `buildings`，使客户端能够在提交前查询成本、区域、槽位、岗位及炉律/科技前置；不直接推荐应建造什么。

## 日结确认与警告阶段

- `game.confirm_end_day` 的命令规格明确确认令牌、状态序列和风险签名均来自同一预览。
- 强警告预览、无预览拒绝与正式观察共用同一份 `confirmation_lifecycle`：令牌范围为当前 `GameSession`，必须在同一存活会话内先预览后确认；关闭或重连会话、状态变化都会使既有确认不可用。
- `RiskWarning` 新增稳定 `assessment_stage`。风险评估器在日结前产生的警告标记为 `pre_settlement`；日结处理器在结算中新增的事实标记为 `settlement_result`。因此“结算前仍有遗体”与“同次结算后墓园已处理”可以同时成立而不再被误读为状态冲突。
- 阶段字段进入正式响应、会话输出和回放；不改变警告等级、确认门槛、风险签名的事务绑定或任何结算顺序。
