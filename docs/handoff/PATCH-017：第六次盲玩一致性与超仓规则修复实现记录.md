# Patch 017：第六次盲玩一致性与超仓规则修复实现记录

## 来源与范围

本补丁依据第六次完整 D1～D55 盲玩报告、正式存档、完整命令历史、回放、关键日机器观察及专项核验记录施工。Patch 016 的 D49～D55 强制停工修复已经由专项证据验证通过；本轮只处理新确认的一致性、文字接线、命令反馈和仓储生产边界。

本轮不调整誓言、铁腕、医疗效果、住房、资源产出、终霜强度或其他平衡数值。

## 已完成

1. 固定增员的风险预览不再读取日结后才同步的陈旧医疗容量。同日建造、派员或撤员后，预览和正式选择都会按当前建筑、合法岗位、温度与科技状态重新计算医疗建筑容量、有效容量和医疗缺口；生成预览不污染原状态。
2. 接入已经封存的“孩子们的请求”标题、正文和三个选项，三次固定增员标题、三个通用接纳选项、两条接纳提示，以及“第七霜落”标题。没有把仍未封存的固定增员正文或第七霜落正文写成正式文字。
3. `INVALID_COMMAND_FORMAT` 结果新增稳定、非策略性的请求字段说明与 JSON Lines 合法命令格式示例。示例只说明协议形状，不推荐行动或替玩家决策。
4. 仓储生产边界按用户明确确认口径接入日结：在生产阶段开始时计算当前仓储占用；若占用量大于等于容量，普通地表采集、建筑生产及会增加仓储占用的食堂加工全部停止，并在结构化日志与风险提示中说明原因。
5. 若生产阶段开始时尚未满仓，当日全部产出和食堂加工结果均保留，即使由此越过容量也不截断、不删除；下一生产日若仍未释放容量，才停止普通生产。固定增员和事件给予的资源仍可直接形成超仓状态。
6. 同日食物预警投影复用相同的生产阶段边界，并先计入正式结算顺序中更早发生的炉心煤耗、过载煤耗与 woodfuel 木材消耗，避免预警和正式日结对“是否已腾出仓位”产生分叉。

## 用户明确确认的仓储口径

- 判定时点是日结生产阶段开始，不是白天任意命令执行时点，也不是前一日结束时的缓存值。
- `storage_used >= storage_capacity` 时停止普通地表采集、普通建筑生产和会增加总仓储占用的食堂加工。
- `storage_used < storage_capacity` 时允许该日完整生产；越界产出全部保留，下一生产日再按新占用量判定。
- 固定增员和事件资源允许越过容量。
- 不按资源类型抢占容量，不自动丢弃、截断或回收任何资源。
