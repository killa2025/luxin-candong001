# PATCH-015：盲玩一致性与机器反馈加固实现记录

## 目标

根据第四轮 seed 7319 盲玩证据，先修复能够确定复现的结算一致性问题，再补足会直接影响沙盒 AI 理解行动后果的结构化反馈。本补丁不调整任何平衡数值；三张地图的独立盲玩与路线平衡复核留到本补丁审核合并后进行。

## 已修复问题

### 配给预览与正式结算一致性

- 食物风险预览继续按当日预计建筑运行状态计算。
- 正式食物结算改为读取供热阶段已经确定的食堂实际运行状态，不再在炉心燃料已经扣除后重复推算供热。
- 因此前已经选择粗汤且食堂实际正常运行时，预览和正式结算会使用同一配给倍率。
- 若食堂实际不可运行，状态、日志和强预警会同时返回已选配给、实际配给和降级原因。

### woodfuel 结果解释

`game.woodfuel` 仍只启用当日应急燃料，不改变原有换算、上限、整档供热或燃料扣除规则。命令结果新增：

- 预计目标炉心档位和有效档位；
- 可用木材、实际等效贡献和预计燃烧木材；
- 零贡献的明确原因；
- 投影范围说明。

这样可以区分“命令成功启用但木材不足以补足下一整档”与命令失败。

### 资源供应锁死与终霜停工

- 当钢材筛选尚未完成、没有小型钢矿机，且现有钢材加剩余地表钢不足以支付该科技成本时，风险预览返回不可逆钢材供应锁死强警告。
- 科技机器视图同步返回资源缺口和不可逆锁死标记。
- D48 风险预览会明确列出 D49 起被第七霜落强制停工的已建造采集建筑。
- 终霜观察视图也提供同一组停工类型和受影响建筑 ID。

以上均为既有机制的可见化，不新增资源、补救命令或停工例外。

### 命令与路线语义

- 命令规范可声明参数语义；`game.assign`、`game.assign_resource` 和誓言/铁腕设施派员明确为“绝对目标人数”，撤员命令明确省略数量会清空对应分配。
- 誓言/铁腕路线视图新增入口炉律、炉律前置与信任/恐慌变化、行动成本/冷却及设施最低总人数。
- 会话观察状态新增炉律视图与科技视图，状态摘要新增已选/实际配给及降级原因。

## 第一轮复审修正

- “共享用餐”的行动视图不再把配置内部的动态公式标记 `-1` 暴露为实际成本；改为按当前存活人口返回真实熟食成本，并用结构化字段公开人口来源、二分之一倍率、向上取整及 30～80 上下限。
- 所有誓言/铁腕行动均公开对应路线设施 ID、设施为必需条件及当前是否运行，与命令的 `route_facility_not_running` 拒绝保持一致。
- 正式地表采集、采集建筑运行、风险预警和终霜观察统一复用 D49～D55 采集停工判断。
- D48 强警告同时列出受影响的建筑和未耗尽/已派员地表资源点；即使没有受影响建筑，也不会遗漏地表停工。
- 钢材供应锁死只计算终霜前仍可采集的地表钢：D48 按当前派员及整数余数计算当日确定产量，D49～D55 为零，不再把冻结的剩余储量当作可回收资源。
