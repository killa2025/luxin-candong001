# Patch 022：合并后盲玩修复记录

## 来源与范围

本轮依据 Patch 022 合并后 seed `22022`、`rustbone_tundra` 的唯一纯黑盒局施工。该局到达 D55，取得 13 分 `bitter_victory`。本轮只处理用户从报告中明确确认的两项问题，不开始 Patch 023，不调整 D49、结局分档、地图、产能、社会路线或其他平衡值。

测试者在 D16 最终签署火盆；“暂不签火盆”是其为了观察早期压力而做的暂缓选择，因此该局不是完全无约束的最优策略样本。它仍是合法黑盒局和有效缺陷证据，但不能单独证明 Patch 022 的最终通关率。

## 整夜停炉最低死亡

- 当日正式日结的实际有效炉级为 0，并且炉心确实关闭或因燃料不足发生供热缺口时，整夜停炉必须产生死亡后果。
- 疾病、饥饿继续按既有顺序优先占用自然死亡额度。若两者已经造成至少 1 例实际死亡，不额外强加一例冻死；若两者均未造成死亡且仍有人存活，寒冷死亡最低为 1。
- 该死亡仍由寒冷系统结算为 `cold_exposure`，受既有自然死亡软上限约束，并进入人口、遗体、日志、回放和后续事件统计；没有另建平行死亡系统。
- `survival.furnace_off` 与实际可负担炉级为 0 的 `survival.heating_fuel_shortfall` 会明确返回最低死亡人数与死亡原因，不再只给强烈语气。

## 首次超仓即时反馈

Patch 017 的仓储规则保持不变：生产阶段开始时未满仓，则当日全部产出保留，即使越过容量；下一生产日若未腾出空间才停止普通生产。

新增的是时序反馈：当普通生产在本次日结首次把库存从未满推到超仓时，同一次成功结果立即返回 `survival.storage_over_capacity_formed`，包含产前占用、产后占用、容量、超额量、当日产出已保留及次日停产条件；同时写入确定性日结日志。该警告不是事前风险确认项，不会伪称在生产前已知准确产后库存。

## 测试与边界

- 连续两个普通日实际停炉时，每日均至少记录 1 例寒冷死亡。
- D1 既有停炉死亡上限、寒冷余数、医疗恢复及自然死亡顺序保持回归。
- 炉心关闭和燃料不足预览均返回最低死亡字段。
- 首次产出形成超仓的同一次日结结果与日志立即出现警告；全部产出继续保留，下一日生产继续按既有规则停工。
