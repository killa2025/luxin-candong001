# Patch 020：终局封存文案与确定性报告实现记录

## 来源与目标

本补丁读取第六轮终局文案资产、Patch 009 A 干净封存版、Patch 010 结构化报告实现和用户本轮补充的死亡记录正文。目标是在不新增游戏机制、不修改平衡数值的前提下，把已经封存且能由机器状态直接证明成立的正文接入正式终局报告。

用户本轮补齐并覆盖了五种死亡记录句：无死亡、墓园、冷藏坑、未处理遗体与余烬名册。正文不得添加“本局共有”。无死亡句同时覆盖 Patch 010 的旧处理：总死亡为 0 时现在正式显示“没有任何人被霜落吞噬，你做得很好，执政官。”；霜落死亡为 0 时仍不另写重复的“最后七天死亡”句。

## 正式报告内容

- 存活结局从对应的高质量胜利、标准胜利、惨胜、崩坏幸存或残火未灭封存主文案池中选择一段。
- 叙事报告接入开局人口、死亡处理、第七霜落死亡、病患、信任/恐慌、炉心、煤炭/食物与未来句。
- `total_deaths` 读取累计死亡人数；`unhandled_bodies` 读取档案封存时未处理遗体数；`start_population` 由历史总人口扣除固定增员解决历史中的实际加入人数得到。
- 死亡记录优先反映未处理遗体，其次反映实际墓园或冷藏坑路径；没有物理处理路径时才使用已签署的余烬名册记录句。余烬名册与实际死亡处理可以作为独立路线痕迹同时保留，不把器官利用或灰烬肥料写成已经消费了具体遗体。
- 重大状态附加句先由 `major` / `defining` 标签确定主题，再逐条核对正文需要的事实并按结局档位限制数量：终霜死亡句要求 `frost_deaths > 0`；`medical.03` 要求同一座终局正在运行的医疗建筑同时派驻正式医生与医疗学徒。`BuildingState` 没有建造日期，`FrostDayRecord` 也没有当天医疗建筑、运行状态或容量快照，因此终局医疗建筑不能证明疾病死亡当天存在医疗服务；`medical.01` / `.02` 暂停正式选择与运行时注册。不能由事实证明的生食、过载或医疗句会从候选中排除。
- 当前状态没有保存“第七霜落期间食堂实际运行过”的历史，因此 `ending.additional.food.01` 与生食经历句一起退出正式候选；食物主题只保留不虚构食堂经历的 `food.02`。
- 路线痕迹严格检查实际签署、使用或建筑存在。完整誓言摘要不会只因进入誓言路线就出现，完整铁腕摘要不会只因进入铁腕路线就出现。`ending.trace.children_protected` 同时暗示互斥的医疗与工程学徒路线，按六轮文案总收口撤出正式注册表并继续登记为 PENDING。
- 存活报告默认显示一条与结局档位匹配的执政官拷问文案；硬失败使用对应原因、可用的失败正文和封存收束句。

## 确定性选择

候选文案先按终局结果、标签、已签署炉律、实际行动、建筑与日期过滤。池内选择使用 `section_key` 的稳定摘要与存档种子派生局部种子，再交给项目统一的 `DeterministicRandom` 选择索引；唯一游戏种子仍来自存档。

该选择不读取 JSON 字段顺序、不调用系统随机源，也不推进游戏主随机流。相同初始状态、相同种子和相同行动序列得到相同 `body_text_ids`；重复查看、存档读取和回放不会重新抽取。正式随机权重仍未封存，因此当前按封存许可使用无权重选择，不自行设置偏好概率。

## 存档与严格校验

技术主窗本轮裁决：不放宽“新报告删除正文必须拒绝”的严格合同，采用显式报告格式版本与正式存档迁移解决旧报告兼容问题。

- 存档版本由 v14 提升到 v15，`EndingReportState` 新增明确的 `format_version`。Patch 010 已生成的 v14 报告迁移为格式 1；未生成报告和 Patch 020 新报告固定使用格式 2。
- 严格读档按报告格式分别校验。格式 1 只接受完整的 Patch 010 旧形状；格式 2 只接受按当前终局状态与种子重新计算出的完整正文。新报告删除正文再替换为旧 pending 集合，因仍是格式 2 而必须拒绝。
- Patch 010 已生成的 v14 部分报告迁移后仍使用原始正文与 pending 集合，不在加载时偷偷补抽或改写；`game.end_run` 若正式重建展示报告，则显式升级到格式 2。新旧格式不能混搭。
- `game.end_run` 仍保持幂等和 D55 边界；主动封存正文也按同一存档种子稳定选择，不修改人口、资源、社会值、评分、标签或随机流。

## 测试

- 同种子终局报告完全一致，不同种子可以选择不同的合法候选；查看报告不会重抽。
- 五种用户确认死亡句逐字验证并确认不包含“本局共有”；未处理遗体优先级、墓园、冷藏坑、余烬名册和无死亡分支均覆盖。
- 零霜落死亡时任何种子都不能选择“没能熬过最后七天”；零疾病死亡时即使存在医疗标签和床位溢出，也不能选择病患死亡句；医疗学徒句只在同一座运行医疗建筑同时存在正式医生与医疗学徒时进入候选。
- 即使终局存在医疗站，且同一终霜记录同时写有疾病死亡和医疗溢出，在缺少当天医疗服务历史时也不能选择 `medical.01` / `.02`；两句不进入 TextRegistry，并以稳定 PENDING ID 登记。只有同一终局运行医疗建筑同时存在正式医生与医疗学徒时才允许 `medical.03`。
- 全局没有食堂时遍历多随机种子均不能选择 `food.01`；因缺少食堂运行历史字段，即使终局存在食堂也不据此反推终霜期间曾经开锅。
- 霜落死亡为 0 时不输出重复的霜落死亡句，但总死亡为 0 时输出新确认的无死亡句。
- 跨结局正文篡改和未知 pending ID 被严格读档拒绝。
- Patch 010 旧 v14 部分报告迁移为 v15 / 格式 1 后保持正文原样，并仍可通过正式报告入口查看；格式 2 新报告伪装成旧正文集合会被拒绝。
- 009-C 长文只进入稳定、去重、排序的 `pending_text_ids`；封存正文中不出现 `.pool`、`TODO_TEXT` 或 `PENDING` 占位。
