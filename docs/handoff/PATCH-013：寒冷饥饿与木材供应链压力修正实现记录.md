# PATCH-013：寒冷饥饿与木材供应链压力修正实现记录

## 一、目标

根据两轮 D1～D55 纯盲玩暴露的问题，补齐会让重大生存失误产生持续后果的基础压力：

- D1～D55 有房与无房人口分离的寒冷暴露；
- 正常、轻度、重度、濒饿四个互斥饥饿池；
- 饥饿导致的疾病、重症、死亡、信任与恐慌压力；
- 更保守的额外医疗配给试玩值；
- D49 木材供应链已经不可恢复时的结构化限制因素；
- 终霜食物评分读取整局可复现的饥饿事实。

本 Patch 不改仓储规则、誓言/铁腕路线加成，不补写终局候选正文，也不实现 AI 策略。

## 二、寒冷暴露

- D1 正常无房不直接死亡；炉心关闭或严重热量缺口时，当日寒冷死亡最多 1 人。
- D2 起按有房/无房、暴露等级和伤残/死亡分别保存整数余数；小人口会累积风险，但不会因每天向下取整而永久免疫。
- 人口离开某一暴露等级后，该等级余数停止增长；全部计算可保存、可回放。
- 医疗剩余容量只缓解寒冷伤残，不抵消寒冷死亡。
- 资料没有封存“连续三级暴露额外死亡”公式，因此没有自行增加该机制。

## 三、四层饥饿

四池必须互斥且合计等于当前在城存活人口：

```text
hunger_none + hunger_light + hunger_severe + hunger_starving
= population_alive
```

- 进食优先级：濒饿→重度→轻度→正常。
- 已进食人口恢复一层，未进食人口恶化一层；每天只做一次同步迁移。
- 新正式增员进入正常池。
- 饥饿疾病按 1/5、重症按 1/6、死亡按 1/8 结算；信任按 1/20、每日最多 -6，恐慌按 1/15、每日最多 +8。
- 疾病死亡先占自然死亡软上限，其次是饥饿死亡，最后是寒冷死亡；饥饿死亡只能从濒饿池扣除，溢出人员仍留在濒饿池。
- 全部比例使用整数商与可保存余数，不使用浮点数。

当前没有个人身份×健康×饥饿交叉表。负责人本轮明确确认的确定性兜底规则为：非饥饿死亡或离城按正常→轻度→重度→濒饿依次扣除；批量与逐笔扣除必须一致。饥饿死亡不得转扣较轻层。将来有真实身份交叉记录后，应按实际死亡或离城者的饥饿层替代该兜底。

## 四、医疗配给与木材断链

额外医疗配给使用负责人确认的 `TEST_NUMERIC`：

- 每名实际接受治疗的病人消耗 5 熟食；
- 每次最多 10 人、50 熟食；
- 冷却 5 天；
- 只在正式医疗设施可运行时生效；病患立即治愈，重症获得既有进度；不治疗伤残或死亡人口，也不为空名额付费。

D49 同时满足下列条件时记录 `wood_supply_locked`：地表木材耗尽、没有已建成且当时可运行的合法伐木场、没有其他已封存替代来源、库存木材低于建造伐木场所需 35。该状态不是硬失败，但最好结局限制为 `collapse_survival`，并进入终局报告的 `limiting_factor_ids`。检查不凭空创建施工队列、补救资源或替代机制。

## 五、终霜食物评分

系统保存整局饥饿天数、未进食人日、最差单日未进食比例与饥饿死亡；D49～D55 另保存同口径终霜统计。食物评分取三项中最低档：

- 饥饿天数：0～1 / 2 / 3～4 / 5+；
- 峰值未进食比例：低于 10% / 10%～低于 25% / 25%～低于 50% / 50%+；
- 累计未进食人日比例：低于 5% / 5%～低于 15% / 15%～低于 30% / 30%+。

终霜发生饥饿死亡时食物分最高为 1。比例边界全部用整数交叉比较，避免浮点误差。上述阈值均为 `TEST_NUMERIC`。
