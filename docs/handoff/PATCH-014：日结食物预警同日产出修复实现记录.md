# PATCH-014：日结食物预警同日产出修复实现记录

## 目标

修复 seed 7319 盲玩发现的日结食物强预警误报。此前风险预览只读取日结前现有熟食与生食，没有计入 `RESOLVE_COLLECTION_AND_PRODUCTION` 阶段早于食物消耗发生的当日建筑产出，因此可运行温室足以供餐时仍会报告大量人口缺食。

本补丁只修复预警与正式日结不一致，不修改食物消耗、生产数值、寒冷、医疗、住房、誓言、铁腕、信任或恐慌规则。

## 实现

- 建筑系统把既有建筑生产与食堂加工提取为同一内部结算路径，正式日结继续调用该路径，产出顺序与整数余数语义不变。
- 新增只读食物库存投影：复制完整游戏状态，在副本上按预计炉心供热、建筑温度、合法配员和终霜停工规则确定当日可运行建筑，再调用正式建筑生产与食堂加工路径。
- 风险预览使用投影后的熟食与生食总量计算 `survival.food_shortfall`、缺口与未进食人口。
- 强警告详情同时返回日结前库存、投影库存、当日生食产出、生食加工量和熟食产出，供机器玩家区分库存与同日产出。
- 投影不会修改正式资源、建筑运行状态、生产整数余数、工时倍率余数或存档。
- 没有建筑配置的基础生存测试仍按当前库存计算，保持 Patch 003 的独立运行能力。

## 盲玩问题复核

- D50、D51、D53、D54、D55：温室与食堂可运行时，当日产出应进入预警计算，不再产生虚假的缺粮强警告。
- D52：炉心关闭导致温室与食堂因温度停摆，当日产出为零，真实缺粮强警告继续保留。
- 终局报告正文为空属于此前已登记的未封存文案 PENDING，不在本补丁自行编写。

## 第一轮复审修正

- 建筑运行预测不再分别推断炉心档位与过载温度，而是统一读取 `projected_heating()` 返回的同一个 `HeatingProjection`。
- 建筑温度只使用 `effective_overload_level` 对应的温度加成；目标过载因基础供暖付款后剩余煤不足而失效时，不再提供虚假温度。
- Patch 014 食物预警测试注入正式 `TechnologyRules`，覆盖真实过载费用、解锁与温度路径。
- 补充 D50 炉心 2 档、目标过载 1、煤 100 的复现：基础供暖支付 85 后仅剩 15，温室停产，预警与正式日结均报告 80 食物缺口。
- 补充木燃料承担基础供暖缺口后没有剩余煤支付过载，以及 D55 食堂仅在虚假过载温度下才可运行的边界。

## 测试

- 普通天气下，同日狩猎小屋生食产出经食堂加工后足以供餐时，不产生缺粮强警告，实际日结也无缺口。
- D50 两座温室与食堂可运行时，预警投影与正式日结均判定无缺口。
- D50 炉心关闭时，温室与食堂投影产出均为零，强警告和实际日结均报告 80 食物缺口。
- 重复生成预警不会改变原状态或消费生产余数。
- 全量 `unittest`：369 项通过。
