# Patch 030：终局路线与制度长文收口实现记录

## 1. 完成范围

本 Patch 只接入用户明确确认并在本轮校正过事实边界的终局长文：

- 誓言、终火誓约、铁腕、最高戒令四种路线正文；
- 旧城派四种结算正文，以及承诺成功/失败两种附加正文；部分/大规模出走现有正文只在实际离开大于 0 且至少一种实际资源损失大于 0 时运行；
- 儿童低风险辅工、全岗位童工、保护炉律未建保护所、只建保护所、建成学校、医疗方向、工程方向七种正文；
- 未运行娱乐设施、运行小酒馆、运行大赌场三种正文进入事实选择；镇静之城正文原文保留，但因正式触发公式尚未封存而暂停运行时注册；
- 死亡处理继续使用 Patch 020 已确认的五种动态死亡记录句，不再追加同主题重复段落。

没有修改炉律、旧城、建筑、资源、人口、终霜、评分、随机权重或任何平衡值，也没有实现 UI、D56 或新游戏机制。

## 2. 正式选择口径

新生成的生存终局报告使用报告格式 5，并按以下稳定顺序追加正文：路线、旧城结算、旧城承诺、儿童制度、娱乐制度。

1. 终火誓约生效时只使用终火誓约正文；否则誓言路线使用普通誓言正文。
2. 最高戒令生效时只使用最高戒令正文；否则铁腕路线使用普通铁腕正文。
3. 旧城已解锁时，散去与未解决正文可直接按正式 `result_id` 选择；部分/大规模出走还必须满足 `actual_departures > 0` 且 `settlement_resource_losses` 至少一项大于 0。否则现有正文会虚构离开或资源损失，格式 5 省略该段并返回稳定的 `ending.old_city.full_text` PENDING。承诺已经结算时，仍可独立按正式结算结果追加成功或失败正文，二者互斥。
4. 儿童正文只读取已经签署的炉律与已经建成的儿童保护所、学校。全岗位童工优先于低风险辅工；保护路线再按保护所、学校与互斥学徒方向选择。正文不声称尚未由机制生成的学徒人口已经存在。
5. 娱乐正文只在签署小酒馆或大赌场炉律后进入报告，并按终局实际运行的大赌场、小酒馆选择；均未运行时使用“无运行设施”正文。旧设计中的 `sedation_city` 不在当前正式标签配置中，也没有可执行触发公式；Patch 030 不新增该机制，镇静之城正文暂停运行时注册，并以 `ending.entertainment.sedation_city.full_text` 稳定登记 PENDING。
6. 同主题的一句式路线痕迹会被格式 5 长文替代，避免同一事实重复叙述。
7. 主动封存和硬失败报告保持既有结构，不追加“炉城撑到最后”类生存长文。

## 4. 报告与存档兼容

- 存档数据版本保持 v17，不新增存档迁移。
- 当前报告格式由 4 提升为 5，只用于尚未生成报告的终局。
- 已生成的格式 1、2、3、4 报告保持原 `body_text_ids` 与 `pending_text_ids`，加载时不重抽、不升级、不改写。
- 严格校验按每个历史格式各自的正文与 PENDING 合同复算；删除格式 5 正文、把格式 4 形状伪装成格式 5，或向报告加入不满足事实的正文都会被拒绝。
- 格式 4 历史 PENDING 即使不再属于当前运行时 PENDING，仍可由查看接口读取，不会因为 Patch 030 的收口而损坏旧报告。

## 5. 验证范围

- 四种路线优先与短摘要替换；
- 旧城四种结果、实际出走人数插值、承诺成功/失败互斥，以及零实际离开、零实际资源损失的严格读档 PENDING 边界；

- 三种可运行娱乐分支与终局实际运行状态；镇静之城正文不会被伪造标签接入正式报告；
- 21 段用户确认原文完整保留，其中 20 个 `text_id` 进入 `USER_OVERRIDE` 运行正文，镇静之城正文因触发公式缺失保留为 PENDING；
- 格式 4 严格复载、格式 5 防伪与当前 PENDING 去重；
- 全量 472 项 unittest、9 份 JSON 配置校验、`compileall` 与 `git diff --check` 均通过。
