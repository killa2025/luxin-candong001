# Patch 027：终局事实与机器查询收口实现记录

## 来源与范围

本轮依据 Patch 026 合并后的第二十二次 D1～D55 纯黑盒验收，修复两处终局正文与正式状态直接矛盾、一个医疗警告 ID 误导，以及两类必须靠失败猜测的机器接口。

本轮不修改任何地图、资源、建筑、科技、炉律、事件、社会路线、天气、终霜或评分平衡值；不补写 `TODO_TEXT`，不提供行动推荐、自动策略、图形界面或 D56。

## 终局事实筛选

- 病患主报告句改为读取 D55 的 Patch 021 服务快照。只有 `service_history_known=true`、运行医疗建筑数大于 0 且医疗建筑容量大于 0，才允许显示明示医疗站仍在运行的封存正文。
- 终局仍有病患、但 D55 无法证明医疗服务运行时，省略病患句并登记 `ending.report.illness.no_operational_service`；不自行写替代正文。
- 煤炭/食物合并句同时检查终局实际库存。煤炭为 0，或生食与熟食合计为 0 时，三条均暗示两者尚有余量的现有正文全部暂停，登记 `ending.report.coal_food.zero_stock`。
- 其他终局选择、确定性随机派生、主随机流、评分和标签均不改变。

## 报告格式兼容

- 新生成报告使用格式 3，严格校验新的事实筛选与稳定 PENDING 集合。
- 格式 2 报告继续按 Patch 020/021/022～026 时期的既有选择合同严格读取，不在加载时重抽或静默改写。
- 格式 1 的 Patch 010 旧报告兼容保持不变。三种格式不能互相伪装；当前游戏存档结构未改变，存档版本仍为 v17。

## 机器查询与反馈

- `play` 长连接正式支持 `{"type":"status"}` 与 `{"type":"command_specs"}`，均为只读请求，不改变 `state_sequence`。
- 未知包络返回稳定排序的 `supported_envelope_types`；完整观察的协议合同同步公开请求形状，不包含策略建议。
- `mourning_bell` 行动规则公开 `requires_recorded_death` 与当前是否满足，执行时原有 `no_death_to_mourn` 合法性规则不变。
- `laws.day4_medical_gap` 只用于 D4；D5 及以后相同的零医疗容量风险使用 `laws.medical_capacity_gap`，风险等级与数值结算不变。
