# Patch 009：第七霜落与终局评分实现记录

## 完成范围

- 新增 `data/final_frost.json` 与严格加载器，登记 D49～D55 真实温度、展示标签、外勤停工目录、终霜伤害公式、每日事实阈值、D49 准备评估、六系统评分、结局分档与标签严重度；未最终封存的平衡值统一保持 `TEST_NUMERIC`。
- D49 进入第七霜落时一次性保存人口、健康、伤残与可工作人口基线，并按煤炭、食物、住房、医疗覆盖、信任、恐慌、旧城派与关键科技八项生成结构化准备结果。食物项只读取检查时实际库存：熟食按 1:1 计入；食堂同时满足已建成、合法派员，并通过统一的 D49 当天预计运行校验（D49 天气、炉心、燃料、保温、科技及当天 heat 状态）时，生食才按 1:2 熟食等价值计入。该检查不读取 D48 遗留运行缓存，不消耗、不转换库存，也不预估 D49～D54 未来产出。
- D49～D55 强制关闭狩猎小屋、伐木场、小型采煤机与小型采钢机，并暂停全部地表资源点采集；停工不消耗资源点储量，也不伪造产出。
- 接入终霜寒冷暴露、疾病恶化、治疗进度、重症、伤残、疾病死亡与寒冷死亡；所有结果均使用整数公式和既有事务日结，不引入不可复现随机分支。
- 自然死亡使用 `min(22, 12 + floor(max(0, alive - 80) / 35))` 基础软上限；疾病死亡先占额度，寒冷死亡只使用剩余额度。至少两项既有极端危机同时成立时，按用户本轮明确确认的暂行口径使用 `(base_cap * 3 + 1) // 2`。
- 超出当日软上限的疾病与寒冷死亡不从人口中扣除，人员留在原健康池；逐日记录原始值、实际值、分类溢出、基础/应用上限、危机条件与总溢出压力，并且仅在总溢出大于零时提交一次结构化事件候选。
- `grave_city` 只按累计死亡人数相对历史总人口严格大于配置中的 30% 触发，使用整数交叉比较；历史总人口包含开局及所有正式增员，旧城派出走后不减少。
- 每日保存煤炭与炉心、供热与建筑低温、食物短缺、住房暴露、医疗积压、伤病死亡及信任恐慌事实；无住所组另行保存自身新增患病、伤残和寒冷死亡，仅以该组事实派生 `frozen_homeless`。D49～D55 记录必须连续、人口链必须一致，温度与展示标签必须匹配配置。
- D55 在既有四种硬失败检查之后，若城市仍存活，则结算煤炭/炉心、食物、住房/温度、医疗/疾病、信任/恐慌、人口/死亡六项 0～4 分，生成 0～24 总分、五档结构化结局 ID，并应用单项崩坏、死亡比例和多系统崩坏上限。煤炭、住房和医疗的明确 0 分崩坏条件优先于 4/3/2 分条件。
- 生成 major / defining 两级结构化结局标签接口，并把评分、标签和每日终霜事实加入机器观察；`unprepared_frost` 优先于 `prepared_for_frost`，`frost_survived_broken` 优先于 `frost_survived_clean`，两组相反标签均在派生阶段保持互斥。未写完整结局正文、审问文本、推荐或自动策略。
- 终霜规则对象递归冻结嵌套评分映射，运行中的实例不能篡改结局分档阈值。
