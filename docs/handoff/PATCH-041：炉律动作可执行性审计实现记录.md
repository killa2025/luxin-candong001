# Patch 041：炉律动作可执行性审计实现记录

## 1. 范围

本 Patch 在 Patch 040 暂停 `game.triage` 后，对正式命令、炉律解锁动作、科技、延后建筑与待定模式效果进行一次可执行性审计。目的不是新增机制，而是确认机器观察不会把尚未封存或不能产生正式结果的能力伪装成可执行收益。

本轮不修改 JSON、平衡值、存档版本、研究、建筑、生产、事件、终霜、终局或社会路线机制。

## 3. `triage_law` 新签署暂停

未签署时，`triage_law`：

- 不进入 `available_law_ids`；
- 不进入普通 `locked_laws`；
- 进入 `unavailable_laws`；
- 返回 `unavailable_reason=triage_rules_unsealed`；
- 同时声明动作 ID、命令名、命令存在且不可执行。

格式合法的 `game.sign_law` 请求若目标为 `triage_law`，稳定返回 `ILLEGAL_COMMAND`。拒绝不签署炉律、不递增状态序列、不消耗普通炉律冷却、不写主存档；拒绝尝试只按现有协议进入本会话回放。

## 4. 旧存档兼容与动作分层

既有存档可能已经签署 `triage_law`。本轮不删除、不退款、不迁移或改写该历史，不提升存档版本，继续保持 v17。

机器观察新增三层事实：

- `declared_action_ids`：已签炉律在配置中声明的全部动作；
- `unlocked_action_ids`：当前能够作为正式已解锁动作使用的集合；
- `unavailable_actions`：已经声明但因规则未封存而暂停的动作及原因。

因此旧档中的 `triage` 保留在声明事实中，但只出现在 `unavailable_actions`，不会继续混入 `unlocked_action_ids`。这不会改变 `game.triage` 自身的兼容拒绝理由或目标合同。

## 5. 测试

新增覆盖：

- 未签署分诊炉律的可用、锁定与不可用列表互斥；
- 直接签署的结构化原因及状态原子性；
- 会话主存档不被拒绝请求改写，回放保存拒绝事实；
- 旧档已签署分诊炉律可以复载；
- 旧档声明动作保留，但不可用动作不混入可执行解锁；
- Patch 040 的目标条件、命令暂停与旧历史字段兼容继续通过。
