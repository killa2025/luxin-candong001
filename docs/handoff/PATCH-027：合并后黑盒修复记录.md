# Patch 027：合并后黑盒修复记录

## 来源与范围

第二十三次 Patch 027 目标导向纯黑盒验收从既有 v17、格式 2 的 D48 存档继续运行时，发现医疗崩溃/死亡分支在 D52 确认日结后稳定返回 `INTERNAL_ERROR`，失败阶段为 `write_autosave`。高温、零死亡分支能够通过同一天并完成 D55。

本修复只处理死亡裁员后的派员派生状态一致性，不改变疾病死亡公式、自然死亡上限、路线设施人员要求、自动保存边界、终局报告、配置或任何平衡值。

## 根因

- 疾病、饥饿或寒冷死亡会通过统一职业裁减保证职业人口和派员总数不超过存活人口。
- 当裁减撤掉守炉堂或巡查所最后一名工人/工程师时，人员数正确变为 0，但 `is_running` 仍保留为 `true`。
- `WRITE_AUTOSAVE` 在生成自动保存前执行严格校验，因此以 `route facility running state must match staffing` 拒绝不一致状态并原子回滚。
- 旧格式 2 不是根因；它只提供了能稳定进入该死亡与派员组合的既有局面。

## 修复

- 统一派员裁减处理完工人或工程师后，依据设施是否启用以及剩余工人和工程师总数，重新派生守炉堂和巡查所的 `is_running`。
- 设施仍有至少一名成人时继续运行；最后一名人员被裁减时立即停运。
- 保留严格存档校验，不用放宽校验掩盖状态分叉。
