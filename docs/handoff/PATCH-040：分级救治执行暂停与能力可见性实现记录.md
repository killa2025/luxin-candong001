# Patch 040：分级救治执行暂停与能力可见性实现记录

## 1. 范围与用户确认

本 Patch 按用户转交的技术裁决采用 A 方案：暂停 `game.triage` 的实际执行。命令 ID、参数 schema、两条已封存目标正文和旧存档字段全部保留；本轮不删除分诊系统，也不把未封存的设计方向变成运行数值。

正式机器语义为：

- `command_exists=true`；
- `executable=false`；
- `unavailable_reason=triage_rules_unsealed`。

`game.triage` 不再出现在 `available_commands`，而在 `unavailable_commands` 和完整 `command_specs` 查询中继续可见。该分离只表达能力可用性，不提供策略推荐。

## 2. 已确认目标边界

- 未来每次成功执行只作用于一座指定建筑，不是全城总开关；
- 医疗站、医院是允许的未来目标；
- 养护所不是急救建筑，不具备分级救治资格；
- 其他非医疗治疗建筑同样不是合法目标。

`law_view.triage_target_contract` 继续返回目标正文，并增加能力状态和 `one_target_per_execution=true`。缺少或类型错误的 `building_id` 仍按统一参数校验返回目标格式说明；这不代表命令可执行。

## 3. 直接调用与兼容

格式合法的直接调用在任何正式状态修改前稳定拒绝。为兼容旧客户端和旧回放，正式拒绝原因继续使用 `triage_balance_not_sealed`，同时返回统一能力原因 `triage_rules_unsealed` 及目标合同。

拒绝不会扣资源、设置冷却、改变患者或医疗压力、产生死亡或伤残、改变信任或恐慌、生成分诊终局事实，或设置新的 `triage_used` 状态。拒绝尝试可以进入当前会话回放，但 `state_sequence`、主存档和既有历史不变。相同状态与输入得到相同拒绝数据。

既有 `triage_building_id`、`triage_used_ever`、历史标签、存档和命令日志继续按原合同读取，不删除、不退款、不回写历史。加载后只影响未来命令的可执行状态；不提升存档版本。

## 4. 当前不得实现

本轮不定义或推断：

- 启动资源成本与冷却天数；
- 单次处理人数及各类病人的治疗结果；
- 被放弃、死亡、伤残人数或比例；
- 成功/失败随机率；
- 医疗压力变化；
- 信任、恐慌或额外事件概率。

“优先救治轻症或高生还重症，濒危或低生还病人可能被延后或牺牲”只保留为设计方向，不生成公式、日志或结果。

## 5. 重新启用门槛

以下 12 项必须全部获得正式口径后，才能另开 Patch 将命令恢复为可执行：

1. 使用前置条件；
2. 合法目标状态；
3. 资源成本；
4. 冷却；
5. 可处理人口范围；
6. 各类病人的确定治疗结果；
7. 死亡结算；
8. 伤残结算；
9. 医疗压力变化；
10. 信任 / 恐慌或“明确无直接变化”的正式规则；
11. 与自然死亡软上限、医疗容量、死亡系统、伤残系统的结算顺序；
12. 存档 / 回放字段与确定性测试。

任一项仍为 PENDING 时，不得由实现侧补值。

## 6. 测试与越界

测试覆盖命令规格不变量、可执行/不可执行列表分离、完整能力查询、目标合同、参数错误提示、合法形状的稳定拒绝、状态与存档原子性、重复输入确定性、回放拒绝事实，以及既有 `triage_used` 存档字段复载。

本 Patch 不修改 JSON 配置、平衡值、存档版本、研究、建筑、生产、事件、终霜、终局或社会路线；不实现 Patch 041、D56、AI 决策和图形 UI。

## 7. 首轮复审修正

- `command_exists`、`executable`、`unavailable_reason` 均为仅限关键字参数，不改变已正式导出的 `CommandSpec(name, required_arguments, ...)` 旧位置参数顺序；
- 命令目录严格要求 `command_exists` 与 `executable` 的类型为 `bool`，拒绝字符串、整数、`None` 等借真值语义混入正式机器合同；
- 原有“可执行状态与不可用原因必须一致”的校验继续保留。

修正完成时实际结果：511 项 unittest 全部通过；9 份 JSON 配置校验、`compileall` 与 `git diff --check` 全部通过。
